`64-75`: _📐 Maintainability & Code Quality_ | _🔵 Trivial_ | _💤 Low value_

**Nested rollback never releases its savepoint.** `withTransaction` issues `rollback to <savepoint>` on the nested error path but no matching `release`. In SQLite, `ROLLBACK TO` reverts the work and keeps the savepoint on the transaction stack, so each caught nested failure leaves an entry behind. The outer `commit` clears the stack, so no data is corrupted, but the stack grows with every caught nested failure inside one long outer transaction. The depth counter and the SQLite stack drift apart.

- `src/db/connection.ts#L64-L75`: append `release ${savepoint}` after `rollback to ${savepoint}` for the nested case, so the rollback pops the savepoint it created.
